# Security

Report suspected vulnerabilities privately to **support@adlrlabs.com**, with
“Security report” in the subject. Include the affected feature, build number,
and minimal reproduction steps. Do not send passwords, API keys, payment data,
or body photos. Do not post exploitable details or private member data in a
public GitHub issue.

Please do not access another person's account, run denial-of-service tests,
exhaust AI quotas, or modify production data to demonstrate an issue. A private
report does not authorize intrusive testing. No bounty or response-time promise
is implied.

Security is an ongoing process. Passing dependency scans and automated tests
does not establish that the application is vulnerability-free. Release security
checks must cover the app, backend, Firebase rules, native builds, dependencies,
and operational account configuration.
